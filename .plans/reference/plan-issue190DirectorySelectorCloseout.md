# Issue #190 目录选择器收口设计正式文档

## 1. 文档定位

本文用于把已确认的 Issue #190 目录选择器设计固化为仓库内正式参考文档，只定义收口目标、统一命名、兼容语义、验证边界与 OpenSpec 收口标准，不包含任何代码实现。

## 2. 收口目标

1. 目录选择器对外收口为单入口、单命名、单验证链路。
2. WebDAV 与 SMB 共用同一套核心三层结构：DirectorySelectorBuilder、DirectorySelectorState、DirectorySelectorAdapter。
3. 所有入口统一经过同一组参数解析与协议校验，禁止出现协议分叉后各自校验。
4. 历史根目录值 " /" 在读取时保持兼容，在保存时一律归一化为 "/"。
5. WebDAV 当前目录自引用项按语义过滤，而不是按数组位置或显示名做脆弱处理。
6. OpenSpec 与验证范围收口到统一目录选择器能力，不再把 SMB 目录选择器定义成一套平行产品能力。

## 3. 非目标

1. 本文不引入新的目录选择业务能力。
2. 本文不改动文件浏览器播放、图片预览、扫描流程或数据库 schema 版本。
3. 本文不要求增加协议专属 UI 分叉。
4. 本文不要求编写一次性历史数据迁移脚本；历史兼容通过读时兼容和写时归一化完成。

## 4. 最终设计

### 4.1 单入口单命名

目录选择器的规范化对外名称统一为 DirectorySelector，规范化设置路由统一为 directorySelector，规范化页面构建入口统一为 DirectorySelectorBuilder。

收口要求如下：

- 新代码、新文档、新测试、新 OpenSpec 表述全部使用 DirectorySelector 这一套命名。
- 协议差异通过 protocolKey 表达，不能再通过新增一套 SMB 专属页面名、Builder 名或测试名表达。
- 已存在的 SMB 命名仅允许作为迁移兼容别名存在，不能继续扩散为新的主命名。
- 日志、注释、设计文档、测试标题都应优先使用“目录选择器”或 DirectorySelector，而不是“WebDAV 目录选择器”“SMB 目录选择器”两套平行概念。

这一定义的目标是让入口名、Builder 名、状态名、适配层名、OpenSpec 名称与测试命名保持一致，避免调用方需要先判断协议，再决定该走哪一套路由或哪一套页面。

### 4.2 共享核心三层

目录选择器收口后只保留一套共享核心三层。

| 层级 | 统一名称 | 责任 | 禁止事项 |
| --- | --- | --- | --- |
| 展示与装配层 | DirectorySelectorBuilder | 负责生命周期、路由参数接入、保存动作触发、页面装配、错误反馈与返回行为接线 | 不直接写协议分支逻辑，不直接拼接协议目录数据 |
| 交互状态层 | DirectorySelectorState | 负责当前路径、面包屑、历史栈、全选态、目录勾选态、别名输入态与保存前状态归一化 | 不直接创建 WebDAVClient 或 SMBClient |
| 协议适配层 | DirectorySelectorAdapter | 负责统一路由参数解析、协议校验、协议客户端装配、目录资源转通用条目、协议差异归一 | 不把 UI 状态或页面控制逻辑带入适配层 |

设计约束如下：

- Builder 只消费已经通过校验的统一描述对象，不自行散落协议判断。
- State 不感知 WebDAV 或 SMB 具体实现，只处理通用目录条目和根路径语义。
- Adapter 负责把协议差异吸收为统一的 DirectorySelectorEntry、rootLabel、endpointSummary 与 load 结果。
- 后续若新增协议，只能新增适配器实现，不能复制第二套 Builder 或 State。

### 4.3 所有入口统一验证

目录选择器必须存在单一验证入口，统一负责“参数读取 → 协议判定 → 必填字段校验 → 统一描述对象生成”。

收口规则如下：

1. 所有进入目录选择器的路径，无论来自新建文件源、编辑文件源、重进选择器还是未来补充入口，都必须先走同一套 route params 解析函数。
2. WebDAV 至少验证 sourceId、baseUrl、username、password 这一组目录选择所需参数；SMB 至少验证 sourceId、host、username、password，并补齐 port、domain 默认值。
3. 任何参数缺失都必须在进入 Builder 业务装配前失败，页面只展示统一错误反馈，不创建协议客户端、不触发目录加载。
4. 协议专属的二次约束同样归适配层统一处理，例如 WebDAV 缺失 baseUrl、SMB 缺失 host 时必须显式失败。
5. 兼容旧入口参数时，只允许在统一解析层兼容，不能把兼容判断散落到 Builder、State、测试和调用方各处。

这样可以保证所有入口拥有一致的失败语义、日志语义与测试边界，也避免某一入口绕过校验后出现“WebDAV 能进、SMB 不能进”或“编辑能进、新建不能进”的分叉问题。

### 4.4 root 历史值 " /" 读写兼容与保存归一化

根目录语义在收口后只有一个规范值："/"。

兼容与归一化规则如下：

1. 读取历史数据时，若目录路径为 " /"，必须按根目录处理，语义等同于 "/"。
2. 读取态的根目录识别必须先归一化再判断，不能把 " /" 视为普通目录路径。
3. 保存前必须对目录路径执行归一化：历史值 " /"、多余空白、等价根路径都统一写回为 "/"。
4. 保存后的根目录记录只能保留一条规范记录 "/"，不能同时出现 " /" 与 "/" 两条重复语义记录。
5. “全部文件夹”判断必须建立在归一化后的结果上；只要最终规范值为 "/" 且没有其他目录记录，就视为全选。
6. 若用户从历史库中读到 " /" 并再次保存，结果必须被无损收口为 "/"，无需额外迁移步骤。

该规则的目标是保证历史数据可继续使用，同时把未来写入统一到单一规范值，逐步清理旧语义扩散。

### 4.5 WebDAV 当前目录按语义过滤自引用

WebDAV 目录列举通常可能返回“当前目录自身”这一项。收口后的过滤规则必须按语义识别自引用，而不是依赖返回列表的第一个元素恰好就是当前目录。

约束如下：

1. 自引用过滤必须依据“当前请求目录”和“返回资源真实路径或等价 href”是否指向同一目录来判定。
2. 过滤顺序应为：先识别目录项，再过滤掉与当前目录等价的自引用项，最后映射为通用条目。
3. 不能使用“直接丢弃第一个目录项”的位置型规则作为最终语义。
4. 不能使用“显示名等于当前目录”这样的脆弱规则替代真实路径比对。
5. 真实子目录即使名称与当前目录片段相似，只要语义路径不同，就必须保留。

这样可以避免不同 WebDAV 服务端因返回顺序差异、显示名差异或根目录表现差异而把真实目录误删，或者把当前目录错误展示成可进入的子目录。

## 5. OpenSpec 收口标准

本次收口以现有两份 OpenSpec 为边界基线。

1. file-explorer-component/spec.md 继续定义“共享浏览核心”能力，目录选择器在该 spec 中只作为统一浏览核心之上的一个场景装配，而不是独立复制一套浏览产品。
2. file-source-ui-tests/spec.md 继续定义文件源管理与目录选择器 UI 验证，但目录选择器能力应以统一入口表述覆盖 WebDAV 与 SMB，而不是拆成两份互不一致的产品能力。

达到收口标准时，应满足以下条件：

- OpenSpec 对目录选择器的能力描述只保留一套主能力模型。
- 协议差异只出现在适配器语义、根标签、端点摘要与协议参数要求中。
- 目录浏览、返回、面包屑、勾选、别名、保存语义全部归入统一目录选择器能力。
- 不再新增 SMB 专属平行 spec 名称来表达同一交互能力。

## 6. 验证范围

### 6.1 必须验证的自动化范围

| 层级 | 验证点 |
| --- | --- |
| 单元测试 | DirectorySelectorRouteParams 统一校验；协议缺参失败；共享 rootLabel 与 endpointSummary；WebDAV 自引用语义过滤；root 历史值 " /" 读取兼容与保存归一化；全选态恢复 |
| 页面或状态回归 | 统一 Builder 在非法参数下只展示错误，不进入目录加载；面包屑、返回上级、全选、别名命名、保存动作保持共享行为 |
| UI 或集成验证 | WebDAV 与 SMB 都从文件源设置进入同一目录选择器能力；浏览子目录；完成保存；保存后目录列表正确展示 |

### 6.2 必须验证的手工收口场景

1. 历史数据中存在 " /" 时，目录选择器打开后仍正确显示“全部文件夹”已选中。
2. 在上述场景下再次点击完成，持久化结果只保留 "/"。
3. WebDAV 根目录与任意子目录下，返回结果中的当前目录自引用项不会展示为可进入目录。
4. WebDAV 与 SMB 都复用同一页面入口与同一命名，不再要求调用方切换两套主入口。
5. 任一入口传入缺失关键参数时，都只出现统一失败反馈，不出现协议客户端半初始化状态。

### 6.3 明确排除在本次验证之外的事项

1. 不验证 WebDAV 或 SMB 的网络连通性上限与服务端兼容矩阵。
2. 不验证文件浏览器的视频播放、图片预览与扫描后续链路。
3. 不验证数据库 schema 升级脚本，因为本次兼容策略不是 schema 迁移，而是读时兼容、写时归一化。

## 7. 风险与控制

| 风险 | 说明 | 控制方式 |
| --- | --- | --- |
| 命名回退 | 新代码继续新增 SMB 专属入口名，导致再次分叉 | 统一以 DirectorySelector 作为唯一主命名，兼容别名不得继续扩散 |
| 校验漂移 | 不同入口各自补丁式校验，形成行为不一致 | 所有入口统一走同一 route params 解析与描述对象生成 |
| root 语义重复 | 历史值 " /" 与规范值 "/" 长期并存 | 读取兼容、保存归一化、重复语义去重 |
| WebDAV 误过滤 | 位置型过滤误删真实目录或漏掉自引用 | 按真实路径语义过滤，不按位置或显示名过滤 |
| OpenSpec 分叉 | 规范继续把 WebDAV 与 SMB 写成两套平行能力 | 统一挂到共享目录选择器能力下，只保留协议差异说明 |

3. 文档没有占位词、未决语句或互相冲突的规则。
