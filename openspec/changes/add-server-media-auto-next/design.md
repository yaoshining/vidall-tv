## Context

播放器已有基于 `PlaybackContext` 和 `EpisodePlaybackManager` 的自动下一集状态机，文件源媒体库与文件浏览器共用倒计时、取消及失败抑制。服务器播放参数目前仅携带服务器与条目标识，切源分支也只覆盖本地媒体上下文。服务器客户端能取得季、集、流地址和认证信息，但 `NextUp` 接口表达的是续播推荐，不保证当前集之后的严格顺序。

ArkTS 严格模式要求上下文模型使用显式接口，不能依赖动态对象或 `any`/`unknown`。服务器请求可能增加进入播放前的等待时间，因此上下文获取失败必须可退化。

## Goals / Non-Goals

**Goals:**
- 让服务器剧集进入现有自动下一集状态机，而不是复制一套倒计时逻辑。
- 以整剧的季号、集号形成稳定连续序列，支持季末跨季。
- 自动和手动切集共用服务器流解析及播放会话刷新路径。
- 保持当前用户设置、提示文案和失败行为不变。

**Non-Goals:**
- 不改变电影播放、服务端推荐算法或已看状态判定。
- 不预下载下一集媒体流，不引入跨服务器队列。
- 不把 `NextUp` 结果作为严格剧集顺序来源。
- 本变更不执行 OpenSpec 归档。

## Decisions

### 1. 新增服务器媒体播放上下文

新增独立的服务器上下文类型，条目在通用展示字段外携带服务器类型、服务器 ID、条目 ID、系列 ID、季号和集号。上下文实现现有跳转接口，使选集面板和自动下一集管理器只依赖统一抽象。

选择独立上下文而非扩充本地 `MediaLibraryContext`，因为本地切源依赖文件路径和文件源认证，服务器切源依赖远端条目标识及客户端协议。独立类型可避免混合两套解析规则。

### 2. 基于完整季集数据构建连续序列

上下文构建器先获取系列季列表，再获取各季剧集，过滤不可播放或缺少必要标识的项，按季号、集号及稳定回退顺序排序。当前条目通过服务器 item ID 定位。Jellyfin 与 Emby共用现有统一客户端；Plex 使用对应季集接口。

不采用 `getNextUp()` 作为顺序依据，因为它受观看状态影响，可能跳过已看集或指向其他季，无法保证“当前集的下一集”。若完整列表获取失败，入口仍按当前参数播放，但不附加上下文。

### 3. 播放入口异步准备上下文

服务器详情页、季详情页及服务器媒体库直播放在导航播放器前调用统一构建器。入口只负责提供系列与当前集标识，不各自实现排序。构建失败记录非敏感日志并退化单集播放，避免上下文附属能力阻断播放。

### 4. 复用状态机，按上下文类型分派切源

`EpisodePlaybackManager` 将服务器上下文视为具有下一项的剧集上下文，继续使用原有倒计时状态。播放器选择目标条目后，根据上下文类型进入服务器参数构建路径：重新读取服务器配置、获取目标流 URL/Header，创建目标播放会话，并更新当前服务器条目、时长、标题和进度上报字段。

自动切换与选集面板共用同一入口，避免手动与自动行为漂移。只有完整切源成功后才提交上下文索引；失败时保留当前条目并调用既有失败抑制。

### 5. 上下文保持轻量且不缓存敏感凭据

条目不保存 token、密码或最终流 URL；切换时根据服务器 ID 重新读取配置并解析流。这样避免认证过期及上下文在页面生命周期内持有敏感信息。图片 URL 可以使用客户端生成的可展示地址，但日志不得输出认证头。

## Risks / Trade-offs

- [进入播放前需要获取多季剧集，系列较大时延迟增加] → 并发或顺序复用现有客户端请求，优先使用已有页面数据；失败时退化单集播放。
- [服务器元数据缺少季号或集号导致排序不稳定] → 过滤无法可靠排序的项目，并用服务端原始顺序作为同键稳定回退。
- [切集期间旧进度上报误关联目标] → 切换前停止旧会话上报，成功装载目标后原子更新条目标识和新会话。
- [流解析失败造成上下文索引与实际播放不一致] → 仅在目标播放参数成功构建后更新索引，并沿用当前集失败抑制。
- [Plex 与 Jellyfin/Emby 字段语义不同] → 在客户端统一模型边界完成映射，播放层只消费显式服务器上下文条目。

## Migration Plan

1. 增加上下文模型与纯排序构建逻辑，不改变现有入口。
2. 扩展状态机和播放器服务器切源分派，并用单元测试覆盖。
3. 逐一接入季详情、剧集详情与媒体库播放入口。
4. 验证 Jellyfin/Emby/Plex、同季、跨季、末集和失败退化。
5. 如需回滚，可停止入口附加服务器上下文；原单集服务器播放路径继续可用。
