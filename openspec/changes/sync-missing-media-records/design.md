## Context

当前播放器已经能在文件不存在时向部分详情页返回 `fileNotFound` 和 `videoId`，但页面只支持删除当前单集，电影详情尚未处理返回结果。数据库能够按电影或电视剧查询关联视频，并具备单视频删除与内部孤立元数据清理能力；现有全局扫描器会发现文件、入库和刮削，范围与本功能的只读存在性核验不匹配。具体行为要求见 `specs/missing-media-sync/spec.md`。

远程文件源至少包含 WebDAV 和 SMB。WebDAV 客户端以异常表达 HTTP 状态，SMB 客户端以结构化结果中的可选错误表达失败。两者均需在不确定错误下优先保留数据。实现必须符合 ArkTS 严格类型规则，并适配 TV 遥控器下的阻塞交互。

## Goals / Non-Goals

**Goals:**
- 建立可复用的目标媒体同步服务，将详情页、远端核验和数据库清理隔离。
- 通过目录分组减少远程请求，同时保持完整路径精确匹配和目标媒体删除范围隔离。
- 用三态结果保证仅删除远端明确不存在的视频，并支持部分成功。
- 以批量数据库操作和孤立层级清理保证电影、集、季、剧最终一致。
- 在三个详情页复用一致的确认、进度和结果状态模型。

**Non-Goals:**
- 不通过本流程发现、导入或重新刮削远端文件。
- 不复用文件源级覆盖扫描，也不推导电影或电视剧根目录。
- 不改变播放器返回协议、文件源配置格式或媒体数据库模型。
- 不把暂时不可访问、鉴权失败或协议未知错误视为文件缺失。

## Decisions

### 1. 新增独立的目标媒体同步服务

服务接收明确类型的电影或电视剧目标标识，并分别通过 `getVideosByMovieId` 或 `getVideosByTvSeriesId` 获取关联视频。服务负责分组、核验、进度汇总和调用数据库清理；页面只负责触发与展示状态。

选择独立服务而不是扩展 `VideoScannerUtil`，因为扫描器的职责包括递归发现、入库和刮削，且其覆盖模式作用于文件源。复用会扩大删除范围，并使“只核验已有记录”难以证明。协议客户端和路径规范化工具仍可复用。

### 2. 以文件源和父目录构建核验工作组

对每条视频记录解析 `sourceId`、父目录和规范化完整路径，以 `sourceId + 父目录` 为组键。每组只调用一次轻量只读目录列举，再用返回条目的规范化完整路径集合核对组内记录。进度以已完成核验的视频数而非请求数计算，从而稳定展示 `x/y`。

路径规范化仅处理协议编码差异、重复或尾部斜杠等不改变身份的表示差异，不进行大小写折叠或模糊名称匹配。这样能减少远程请求，同时避免同目录其他媒体进入清理范围。

替代方案是逐文件发起请求，逻辑简单但会显著增加 WebDAV/SMB 往返次数；扫描公共父目录则可能扩大访问和清理范围，因此均不采用。

### 3. 协议核验统一返回三态组结果

定义明确的核验适配接口，目录列举输出成功文件列表、目录明确不存在或无法确认三类结果。成功列表中的每条目标路径再映射为存在或明确不存在。

WebDAV 仅将 HTTP 404 分类为目录明确不存在；401、其他 HTTP 状态和连接异常均分类为无法确认。SMB 只对当前客户端能够稳定识别且语义明确的“不存在”错误分类为明确不存在；无法稳定区分时全部保守归为无法确认。协议不支持同样归为无法确认。

不使用“任何异常都表示缺失”的方案，因为这会在断网或凭据过期时大规模误删。保守分类可能延迟清理，但满足数据安全优先原则。

### 4. 数据库提供目标 ID 批量清理门面

在数据库层新增按视频 ID 批量删除的组合操作，按安全批次删除 `scrape_info`、`play_progress` 和 `videos`，随后调用公开的孤立媒体清理门面。批次大小预留 SQLite 参数上限余量；若现有关系数据库封装支持事务，则整个组合清理在同一事务中完成，否则确保每个视频的关联删除顺序可重试，并在错误时向上返回失败。

孤立清理沿用既有顺序：空集、空季、空剧，最后空电影。同步服务在清理后重新查询目标媒体是否仍存在或仍有关联视频，以决定页面刷新还是退出。

替代方案是循环调用单视频删除，但会重复触发数据库往返且无法统一处理大批次失败；复用文件源级幽灵视频清理则会越过目标媒体边界，因此不采用。

### 5. 页面使用统一同步状态机

电影、季和剧详情页将播放器返回结果交给统一确认流程。确认后进入 `idle → syncing → completed/failed` 状态，维护总数、已检查数和结果汇总。`syncing` 状态渲染覆盖详情页的半透明阻塞蒙层并截断播放、确认和遥控器重复事件。

同步成功且目标仍存在时，页面重新加载当前详情数据并显示清理数与无法确认数；目标已清空时显示结果后返回上一页。全部无法确认或清理事务失败时保留页面和数据并显示失败反馈。三个页面可复用同步服务、结果格式化和蒙层组件，但保留各自的数据刷新方法。

电影播放入口补充与季、剧详情一致的 `PopInfo` 回调，不修改播放器页面协议。

## Risks / Trade-offs

- [SMB 错误文本或错误码在设备、服务端之间不稳定] → 仅维护经过确认的不存在分类，未识别错误一律保留记录，并用单元测试固定已支持的分类。
- [路径编码形式不一致造成误判] → 在适配器边界统一为协议解码后的完整路径，并对中文、空格、尾斜杠和相似名称建立测试；禁止模糊匹配。
- [批量清理中途失败导致关联数据不一致] → 优先使用数据库事务；若封装受限，采用可重试的固定删除顺序，并只在组合清理完整成功后报告已清理。
- [大剧集目录组过多导致同步时间较长] → 目录级去重、逐组更新进度，并保持阻塞界面；首版不引入高并发，避免压垮 NAS。
- [详情页重复实现造成行为漂移] → 抽取服务、状态类型、结果文案和蒙层组件，页面仅适配目标 ID、刷新和退出动作。

## Migration Plan

1. 先增加类型、只读核验适配器和纯逻辑测试，不改变现有播放行为。
2. 增加数据库批量清理门面与孤立清理公开入口，并通过 DAO 测试验证范围和层级收敛。
3. 依次接入电影、季和剧详情页的返回回调和同步 UI。
4. 通过相关单测、格式化、lint 和 HarmonyOS 编译检查后发布；不需要数据迁移。
5. 若需要回滚，移除详情页同步入口和服务调用即可，新增数据库方法未改变表结构，现有数据可继续使用。
