## Why

用户在文件源设置中新增目录后，必须手动触发全局或局部刮削才能让新视频获得元数据，导致新增目录的视频长期处于无元数据状态。应在目录保存成功后自动对新增目录发起定向刮削，消除手动操作的缺口，同时严格限定范围以避免重复刮削既有内容。

## What Changes

- 目录保存成功后，系统自动对**本次新增且规范化后的目录**发起异步入队刮削任务，不阻塞保存流程、不因后台刮削失败回滚目录保存
- 刮削范围限定为新增目录内的视频，且仅处理**首次入库**视频——首次入库以本次定向扫描执行 upsert 前数据库中不存在该视频记录为唯一判断标准，不得以刮削关联、wasProcessed 或元数据完整度推断；自动任务可复用 incremental + automatic 执行策略，但候选 videoIds 必须严格仅为本轮首次插入的记录
- 目录别名变化不触发自动刮削，仅实际新增的目录路径触发
- 自动刮削任务复用 scrape-task-queue 的完整生命周期，失败任务可在现有任务管理（TopBar 下拉列表）中重试
- 采用增量策略：多次保存累积的新目录在各自保存时独立触发，不重复扫描已处理目录
- 不做跨进程恢复（应用重启后不补跑历史保存事件）、不加设置开关、不归档

## Capabilities

### New Capabilities
- `auto-scrape-new-directory-files`: 自动刮削新增目录文件的编排能力，涵盖触发时机（目录保存成功后异步）、范围解析（仅本次新增且规范化目录、仅本轮定向扫描 upsert 前数据库不存在记录的视频）、别名排除、保存-刮削解耦（不回滚）、增量策略与去重、任务创建与失败重试路径

### Modified Capabilities
- `settings-directory-selector`: 新增目录保存成功后的事件钩子，使 auto-scrape 可观测到保存结果并获取新增目录列表
- `scrape-task-queue`: 支持自动触发的目录范围扫描任务（非全局任务的 scanning 阶段扩展），确保自动刮削任务在队列中享有与用户手动任务相同的生命周期、重试与展示语义
- `scan-flow-integration-tests`: 新增自动刮削流程的集成测试场景，覆盖目录保存后任务自动入队、扫描完成、失败重试等端到端路径

## Impact

- **设置弹层保存流程**: 需在目录保存事务完成后发出异步事件，携带新增目录路径列表及对应文件源信息
- **刮削任务队列**: 需扩展 scanning 阶段支持至目录范围任务（当前仅全局任务使用 scanning 阶段），自动任务的范围标识需区分于手动触发
- **TopBar 任务列表**: 自动刮削任务自然出现在现有任务管理 UI 中，无需额外 UI 变更
- **依赖**: 依赖 settings-directory-selector 的保存事件、scrape-task-queue 的入队与调度、scoped-media-scraping 的文件夹范围语义；自动任务的候选 videoIds 筛选独立于 scoped-media-scraping 的"新增和已修改"模式，严格以本轮 upsert 前数据库记录不存在为准
