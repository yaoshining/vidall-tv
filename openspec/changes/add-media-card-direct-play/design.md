## Context

见 `proposal.md`。当前影视服务器首页由 `MediaLibraryTab` 负责分区渲染、详情导航及播放器返回后的静默刷新；“接下来”和“最近添加”已具备卡片/播放按钮三态视觉，但播放按钮仍采用透明命中，点击最终落到卡片主体。继续观看已有服务器直播放链路，播放器侧已有统一续播决策、服务端进度上报与返回刷新能力。

本改动横跨 TV 焦点/指针事件、服务器媒体解析、播放器导航和服务端进度同步，因此需要在不复制播放状态机的前提下明确入口分流。

## Goals / Non-Goals

**Goals:**
- 让卡片主体和中央播放按钮拥有互斥、可测试的操作语义。
- 让首页所有服务器直播放入口复用同一套可播放条目解析、续播和进度同步流程。
- 保持遥控器焦点和鼠标 hover 三态视觉一致，并避免一次按键触发两次导航。
- 播放返回后静默刷新首页，及时回显服务端最新状态。

**Non-Goals:**
- 不改变服务器详情页、季详情页及其播放按钮行为。
- 不改变播放器页面参数公开结构、near-end 阈值或各服务器进度协议。
- 不新增播放引擎、缓存机制或新的服务器 API。
- 不调整当前遮罩和播放按钮视觉参数。

## Decisions

### 1. 将直播放作为卡片显式回调，而非由外层卡片推断 hover 状态

“接下来/最近添加”卡片组件分别暴露主体点击与播放点击回调。中央按钮改为可命中的独立操作目标，在按钮点击/遥控确认处理完成后阻止主体点击路径；卡片主体继续只负责详情导航。继续观看使用不带遮罩按钮的普通宽卡变体，并保留整卡直播放。

选择显式双回调可在组件边界表达行为契约，也方便验证一次交互只触发一个目标。备选方案是在外层点击时读取指针坐标或 `isPlayHovered` 推断意图，但遥控器确认键没有可靠指针位置，且状态竞态会造成误导航，因此不采用。

### 2. 中央播放按钮参与 TV 焦点流，并将视觉激活与动作焦点统一

播放按钮在卡片激活后成为独立可聚焦目标；指针 hover 或遥控器焦点进入按钮时均触发已有放大/变色状态。焦点离开按钮后恢复普通按钮态，离开卡片后恢复默认态。卡片与按钮之间的焦点转移不得让遮罩提前消失。

备选方案是保持 `HitTestMode.Transparent` 并仅提供指针视觉，但无法满足遥控器对独立播放操作的可达性和确定性，因此不采用。

### 3. 抽取并复用首页服务器直播放入口

`MediaLibraryTab` 提供统一的异步直播放入口，接收服务器媒体条目并完成：校验当前服务器和条目 ID、将剧集/季/系列等容器解析为具体可播放媒体、构造现有播放器参数、打开播放器。继续观看卡片和两个中央播放按钮都调用该入口；详情页导航保持独立。

解析和参数装配优先复用现有服务器详情页/继续观看使用的 source adapter 或播放源服务，不在卡片组件内拼接 URL。备选方案是直接以首页条目生成流地址，但系列或季条目可能不可直接播放，并会产生与详情页不同的鉴权及选集逻辑，因此不采用。

### 4. 服务端进度作为直播放续播输入，播放器统一服务作为决策者

首页条目携带的服务端进度进入现有播放上下文，由统一 playback progress service 在 prepared 后执行有效进度 seek 或 near-end 清理决策。入口不自行调用播放器 seek，也不创建第二套阈值判断。

播放期间继续由现有服务器进度 reporter 执行约 10 秒周期、切后台和退出上报；上报失败只记录错误，不阻塞退出。这样可保持 Jellyfin、Emby 与 Plex 的协议差异集中在既有实现中。

### 5. 用播放器返回结果触发一次首页静默刷新

首页直播放打开播放器时沿用现有返回监听，在播放器关闭后触发服务器首页静默刷新。刷新合并或复用当前防重复机制，避免退出上报完成与页面恢复同时造成并发请求。刷新更新整个服务器首页模型，以覆盖进度条、继续观看顺序及可能受观看状态影响的分区。

备选方案是仅在本地修改被点击卡片进度，但无法反映服务端重排、跨设备变化或完播后移出分区，因此不采用。

## Risks / Trade-offs

- [按钮和卡片事件同时触发] → 使用独立命中目标和单一事件消费边界，并为按钮点击只触发播放器增加回归验证。
- [剧集容器无法直接串流] → 统一走既有可播放条目解析；解析失败时不导航并保持页面稳定。
- [按钮成为焦点后遮罩闪烁] → 卡片激活条件同时包含卡片焦点、按钮焦点和指针 hover，统一清理状态。
- [退出时重复刷新服务器首页] → 复用已有静默刷新节流/请求序列保护，只接受最新请求结果。
- [进度来源单位或 near-end 判断不一致] → 不在首页换算或判断，全部交由现有播放上下文和 progress service。
- [透明命中调整影响鼠标与遥控器行为] → 分别验证指针点击、遥控确认、焦点移入/移出及返回键路径。

## Migration Plan

1. 先拆分卡片主体与播放按钮事件并恢复继续观看卡片视觉，不改变播放器入口。
2. 接入统一服务器直播放入口及可播放媒体解析。
3. 连接续播上下文、进度上报和返回静默刷新链路。
4. 通过 ArkTS 编译后在已连接 TV 上逐项验证三类分区、两种输入方式和进度回显。
5. 若出现回归，可回退独立按钮事件接入，恢复卡片主体导航；现有详情页和播放器数据模型无需迁移。
