## Context

参见 `proposal.md` 的动机。文件源媒体库目前在 `MediaLibraryTab` 中先无条件渲染继续播放区域，再依据加载结果渲染空态或内容，并在空态后继续渲染统计与扫描区域。页面已有 `NavPathStack`，设置模块也已有文件源和影视服务器配置路由，因此无需引入新状态管理或导航机制。

ArkTS UI DSL 要求 `build()` 与 `@Builder` 中只写组件语法；TV 端入口还必须提供明确的焦点反馈。

## Goals / Non-Goals

**Goals:**

- 使用单一、可复用的“是否存在可展示媒体”判断控制文件源媒体库的空态与完整内容布局。
- 复用现有设置页路由，让两个空态操作直达文件源列表和新增影视服务器页面。
- 让两个操作按钮具备遥控器焦点状态和清晰视觉反馈。
- 保持影视服务器数据源的加载、错误和内容布局不受影响。

**Non-Goals:**

- 不改变媒体扫描、刮削、媒体过滤或数据库查询规则。
- 不新增文件源或影视服务器配置流程。
- 不调整有内容媒体库各分区的布局和交互。
- 不为该变更新建 PR，也不归档 OpenSpec change。

## Decisions

### 使用媒体库总量判定空态

文件源媒体库加载完成后，以可展示媒体总量为核心条件判断空态，而不是只依赖“最近添加”列表。这样可避免最近添加为空但电影或剧集仍存在时误显示空态。加载未完成时继续使用加载态，不提前显示空态。

备选方案是沿用 `recentlyAdded.length === 0`；该方案改动更少，但“最近添加”并不等价于整个媒体库为空，因此不采用。

### 将完整内容统一放入非空分支

加载态仅渲染加载视图；空态渲染启动引导及底部统计扫描区域；继续播放和媒体分区仅放在非空分支。由于当前添加文件源后不会自动触发刮削，空态必须保留手动扫描、补全及覆盖刮削入口，避免用户完成配置后仍无法建立媒体库。

### 复用设置页导航契约

在组件普通方法中构造带显式类型的 `SettingsPageParam`，分别导航至文件源设置和新增影视服务器页面。按钮 Builder 只调用方法，避免在 ArkUI DSL 中散落对象字面量及导航细节。

### 使用双按钮并维护本地焦点状态

空态采用两个并列的大尺寸按钮。每个按钮通过独立布尔状态响应 `onFocus`/`onBlur`，焦点态提高背景、边框与文字对比度。相比仅依赖系统默认 focus 效果，这能在电视观看距离下提供更稳定的辨识度。

## Risks / Trade-offs

- [媒体总量与实际可展示列表口径不一致] → 优先复用模型中已按展示规则统计的数据；实现时核对 `MediaLibraryModel` 的统计来源，必要时通过电影、剧集与最近添加集合联合判断。
- [按钮初始焦点未自动落入空态] → 保持按钮可聚焦并遵循页面现有焦点链，不强制抢占顶部导航焦点。
- [设置页返回后空态未即时刷新] → 延续组件现有 `aboutToAppear`/数据库 ready 时的 reload 行为，不引入额外订阅。
- [布局在较小电视分辨率下拥挤] → 使用现有 vp 尺寸体系、受控文本宽度和水平按钮间距，避免固定大面积容器。

## Migration Plan

该变更不涉及数据迁移或依赖升级。部署时直接替换页面实现；若出现回归，可回退 `MediaLibraryTab` 的条件分支、空态 Builder 和导航方法，不影响数据库及用户配置。
