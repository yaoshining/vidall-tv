## Context

当前播放器已经具备 `PlaybackContext`、`MediaLibraryContext`、`EpisodeListPanel` 和切集后重新加载播放源的能力，但剧集列表来源仍然偏向页面预构建结果，缺少独立的本地季集匹配层。`#122` 需要把“当前单集 -> 本地季集列表”的识别逻辑收敛成稳定的本地数据路径，`#123` 需要在此基础上补齐自动下一集、倒计时取消和异常降级。

实现约束来自现有代码与 issue 描述：
- 播放器流程不能实时请求 TMDB API，只能依赖本地 `tv_episodes`、`scrape_info`、`videos` 等已刮削数据。
- 自动下一集当前只在 `MediaLibraryContext` 下启用，`FileExplorerContext` 等其他上下文必须保持兼容。
- 现有切集、标题修正、播放进度保存已经通过已合并 PR 收口，新变更不能破坏这些路径。

## Goals / Non-Goals

**Goals:**
- 提供独立的本地季集匹配能力，将媒体库播放上下文构建改为基于本地已刮削数据和视频匹配结果。
- 为播放器补齐自动下一集交互，包括倒计时提示、取消入口、快捷键处理和失败降级。
- 让自动播放相关设置进入播放器设置体系，并在媒体库场景下生效。

**Non-Goals:**
- 不在播放器流程中引入任何实时网络请求或 TMDB 回源策略。
- 不扩展 `FileExplorerContext`、`JellyfinContext` 等非媒体库上下文的自动下一集能力。
- 不在本次变更中重做完整的播放器 UI 结构，只在现有设置/提示层上补充必要交互。

## Decisions

### 1. 新增独立的 EpisodeGroupMatcher，并由 MediaLibraryContext 复用

`EpisodeGroupMatcher` 负责根据当前单集的本地元数据，从 `tv_episodes`、`scrape_info` 和 `videos` 生成当前季的可播放列表。`MediaLibraryContext` 不再自己拼装所有列表细节，而是把“查本地数据并匹配视频”委托给 matcher。

这样做的原因：
- 把 `#122` 的本地识别逻辑从页面/上下文构建流程中抽离，避免未来自动下一集、快捷键切集、播放器重载各自复制一套列表推导。
- 让缓存粒度聚焦到 “series + season” 维度，便于在同一播放会话中复用。

备选方案：
- 继续把匹配逻辑写在 `MediaLibraryContext.build(...)` 内部：实现快，但职责会继续膨胀，不利于测试和缓存。
- 运行时请求 TMDB 补齐季集：违反 issue 约束，且会引入网络不确定性。

### 2. 自动下一集能力挂在 EpisodePlaybackManager，而不是分散到页面和控制器

自动下一集由 `EpisodePlaybackManager` 统一驱动：负责判断当前上下文是否允许自动播放、获取下一集、启动/取消倒计时，以及最终触发和手动切集相同的切换路径。

这样做的原因：
- `EpisodePlaybackManager` 已经是切集闭环的聚合点，自动下一集应复用同一条切换链路，避免 “手动切集” 和 “自动切集” 两套状态机分叉。
- 页面层只负责渲染倒计时提示和转发快捷键/按钮事件，播放器控制器不需要感知具体的剧集导航策略。

备选方案：
- 在 `PlayerPage` 内直接实现自动下一集逻辑：UI 层会知道太多播放上下文细节，测试也更重。
- 在 `VideoPlayerController` 内实现：控制器会被迫承担 UI 倒计时和上下文策略，职责过重。

### 3. 自动播放设置采用播放器内可持久化配置

自动播放开关和倒计时秒数作为播放器设置的一部分持久化，并在进入播放器时读出；倒计时弹层只在设置启用且存在可播放下一集时出现。

这样做的原因：
- Issue #123 明确要求设置项纳入 `PlayerSettingsDialog`。
- 倒计时时长和开关属于用户偏好，适合跨播放会话复用。

备选方案：
- 仅会话内临时状态：实现简单，但用户每次进入播放器都要重新设置。
- 全局硬编码 5 秒：无法满足 issue 中“可调整倒计时长度”的要求。

### 4. 缺失数据和切换失败统一降级为“不自动播放”

当 matcher 找不到完整列表、没有下一集、下一集文件不可加载或用户手动切集时，系统统一取消倒计时并退回现有播放完成行为，不抛未处理异常。

这样做的原因：
- TV 播放流程必须保守，不能因为自动播放能力影响基础播放结束路径。
- 与 issue #123 的异常处理表一致。

备选方案：
- 强制弹错并阻断页面：会把辅助能力升级成主流程故障点，不符合播放器体验。

## Risks / Trade-offs

- **本地刮削数据不完整导致季集列表残缺** → 允许 matcher 返回已匹配的可播放子集，并让自动下一集在无下一集时自然停用。
- **缓存过期导致切集列表与最新数据库状态不一致** → 缓存仅做进程内会话级复用，并在切换剧/季或明确刷新时失效。
- **自动下一集 UI 增加 TV 焦点复杂度** → 倒计时弹层只提供最小必要交互（继续/取消），并让返回键优先执行取消。
- **设置项持久化位置与现有播放器设置实现耦合** → 优先复用现有播放器设置存储结构，避免引入新配置系统。
