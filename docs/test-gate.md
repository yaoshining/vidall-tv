# 必需测试门禁

单元测试和集成测试使用 `scripts/ci/test_gate.py` 保存执行证据并统一判定。编译、测试和报告发布分别记录：编译成功不能替代测试通过，报告发布失败也不能修改测试结果。

| 输入或执行情况 | 测试结论 | 必需门禁 |
| --- | --- | --- |
| 编译成功，尚未执行测试 | 未执行 | 失败 |
| 设备不存在或设备探测超时 | 未执行，注明设备原因 | 失败 |
| OhmUrl 错误（包含退出码为 0 的异常） | 失败，注明 OhmUrl | 失败 |
| 命令超时、中断或非零退出 | 失败，注明执行原因 | 失败 |
| 结果缺失、损坏、字段缺失或计数矛盾 | 失败，注明结果原因 | 失败 |
| 旧运行记录或旧结果 | 失败，注明过期证据 | 失败 |
| 实际执行数为 0 | 未执行 | 失败 |
| 失败数或错误数大于 0 | 失败 | 失败 |
| 本次正常完成、结果有效、执行数大于 0、全部通过 | 通过 | 通过 |
| 报告生成、发布或上传失败 | 保留原始测试结论，单独报告发布异常 | 不将测试失败变为通过 |

`status.json` 记录 `build_status`、`status`、`gate_passed`、原因、真实计数以及运行标识与 SHA。Summary、Portal、历史记录与 Allure 读取同一判定，不从历史页面或编译日志重新推测成功。门禁诊断条目不是测试用例，不计入真实用例数。

每次执行清理或隔离结果与日志，拒绝以旧产物证明当前测试成功。单测与集成测试共享设备并发组，关闭主动取消；不得杀死全局 hdc。超时清理仅针对本次启动的进程。

## 验证边界

门禁样例使用临时目录、可控日志和本地假命令，覆盖失败和正常路径，无需让真机故障。它验证 CI 判定逻辑，不代表 ArkTS 业务测试已在设备运行。交付 PR 应同时列出样例 CI 与实际设备 CI，并注明后者是否执行、失败或受外部环境阻塞。

`ci-compile-check.yml` 与 `ubuntu-sdk-check.yml` 保留编译检查的独立语义，不作为设备测试通过证据。本次不修改播放器、业务逻辑或凭据加密。

合并保护与工作流结论是两层配置：工作流会对未执行测试返回失败，但是否禁止合并取决于 GitHub 的分支保护 / ruleset 必需检查设置。本次不变更仓库级保护设置。

真实运行 34704387512 的 795 条成功结果补充为脱敏样例，覆盖同名 test 行被 hilog 时间字段插入后重发的格式；只容忍同名重复，不忽略不同用例的缺失结果，逐例计数仍须与汇总完全一致。

集成测试先保存门禁状态产物，并独立推送状态 JSON 及当前摘要，再生成/发布 Allure 和更新 Portal。后续失败不会回滚提前发布的状态；若远端状态推送本身失败，明确报告该异常，本次 Actions 产物仍为权威证据。设备探测失败先复制原始执行记录再退出，以保留超时或命令退出码。
